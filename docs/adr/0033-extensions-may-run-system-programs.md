# Extensions may run system programs

Accepted 2026-10-06 by the user's decision, after the [Raycast deep dive](../research/raycast-deep-dive.md#what-real-extensions-use) (its decision 6). It amends [ADR 0014](0014-optional-native-extension-helpers.md): a native helper is no longer the only way a command reaches a program. An extension may also run programs installed on the system, such as PowerShell, winget or git, and may run them elevated. This follows [ADR 0002](0002-trusted-extensions-and-open-distribution.md), which already counts subprocesses among an extension's legitimate capabilities, since extensions are trusted code. It leaves [ADR 0013](0013-require-wasi-03.md) as it is. The command stays a WASI 0.3 component, and because WASI 0.3 offers no way to start a process, Pane's host starts it. The host does the same for applications ([ADR 0015](0015-host-finds-and-opens-applications-for-an-extension.md)) and web requests ([ADR 0018](0018-extensions-reach-the-network-through-wasi-http.md)).

So Pane gives every command a host function that runs a program. The extension can name the program by an absolute path, or by a name Pane resolves on the system's search path. It passes a list of arguments, so no shell parses a command line unless the extension runs a shell such as PowerShell and gives it a script. It may also choose a working folder, add environment variables and write the program's standard input. The answer is the program's standard output, its standard error and its exit status. A run may ask to be elevated. On Windows, Pane then goes through the system's elevation prompt, which the user can refuse. Windows gives no access to an elevated program's output, so such a run answers only whether the program started and how it exited. A run belongs to the call that started it, as a helper's does: it ends when that call is dropped, when the package's generation ends and when Pane quits. Nothing is gated or asked beyond the prompt the system itself shows.

Native helpers stay as ADR 0014 and [helpers](../helpers.md) describe them, for programs a package ships. Their install rules are about what a package ships and do not apply to the system's programs: a file for each target, checked at install, a Windows file that ends in `.exe`, and no scripts. Their text-only 1 MiB and 30-second limits are provisional for helpers and are not assumed here, since an installer or a package manager can legitimately run for minutes and print a lot. The extension contract specification sets this function's limits. It also decides whether output is streamed while the program runs, and whether ending a run ends the processes the program started (a helper's end today reaches only its own process). Proposed for it: make use visible rather than gated, as network use is. A component that imports the function would be noted at install, and the extension list would say so.

Script commands, which the user wants later, are not decided here.

In Raycast's open-source corpus, 22% of extensions start child processes and 10% of the Windows-listing ones run PowerShell. Where authors reach the limits of the API, they turn to the system's own programs. A helper can start other programs itself, so requiring one would only add a build per target and a process between the command and the program. With trusted extensions, that extra layer protects nothing.
