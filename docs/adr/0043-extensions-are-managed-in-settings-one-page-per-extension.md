# Extensions are managed in Settings, one page per extension

**Amended:** [#154](https://github.com/pane-app/pane/issues/154) (2026)
adds a Capabilities section to the group's own page: each capability with
two or more installed providers is listed with a dropdown of its providers
(the chosen one, or the first installed, in force), the extensions that
use it, and, while the chosen provider cannot serve, who serves instead.
A choice is Pane's own record, and applies to the next call without
reloading anything. Preserve the original text below.

Accepted 2026-10-07 by the user's decision, after trying the default extensions beside Raycast for Windows 2.6.1 (specification #161, its slice 7; ticket #168). It changes where extensions are managed, not how: the operations, their records and their confirmations stay the launcher's own.

Pane's Settings window has an **Extensions** group after Pane's own pages. Its sidebar entry heads the group, with a + menu that installs from a folder, npm or Git, and under it every installed extension has an entry of its own: its icon, its title, and a mark in a word while it is paused, broken or updating. The group's own page lists the installed extensions, what governs them all (automatic updates), what belongs to none of them (the extension runtime's rows, data kept for an uninstalled extension) and the install sources.

An **extension's page** shows its large icon, title, description and source at the top, with the mark in full; its enable switch; an Actions menu with Check for Update, Reload, Clear Cache, Reset Confirmations, Show Source Folder and Uninstall (and what else the extension list holds for it: Retry, why it is paused, development, the network and programs it used); its automatic updates; its preferences, with #143's controls; and its commands, each with its icon, title, alias field, hotkey recorder and an enable switch of its own. A command that only provides root results (a root provider, #164) shows only its switch. The Shortcuts page keeps its cross-extension list of aliases and hotkeys.

The launcher's **"Manage extensions…" screen is removed**, with its paragraphs of explanation and its rows of actions. The launcher has a built-in command, **Manage Extensions**, that opens Settings at the Extensions group, and root search's install rows open Settings' install flow. The core keeps every operation (what each does, against the same records) and hands Settings typed operations — what each is, whose, and whether it is on (`Launcher::extension_operations`) — each run directly (`Launcher::run_extension_operation`) without moving the shared launcher off the screen the user had open. The confirmations an operation asks — disabling or uninstalling what other extensions require, keeping or deleting saved data, deleting retained data — and the previews an install or an update check shows stay the core's own screens, drawn in Settings in place of the page and answered there; once answered, the launcher returns to root search, never to a list. The launcher window draws those screens too while the launcher holds them. (The old list can still be shown as a screen of its own for the core's and the window's tests, `Launcher::manage_extensions`; Pane never shows it.) Messages that sent the user to "Manage extensions" now send them to Settings.

**A command can be turned off on its own.** The switch beside a command records, with its package's record in `installed.json`, that the command is off: it is not offered — no root search row, no computed or indexed results, no alias, hotkey, schedule or service — while the rest of its extension works. Its alias and hotkey are kept, shown as not active, and come back with it. The choice survives restarts, reloads and updates; uninstalling forgets it with the package's record.

Settings' search finds an extension by its title and its preferences by theirs, and opens the extension's page there. Check for Update shows an npm or Git extension's source again as its install preview, which offers Update when there is a newer version or commit; a folder's extension is reloaded instead, and Pane updates its default extensions itself. Show Source Folder opens a folder extension's source folder, or else Pane's managed copy of it.

Managing extensions was a launcher screen led by a wall of text, whose rows were actions ("Disable", "Reload"…) rather than a place to see and configure an extension; Raycast, which users switch from, manages each extension on a page of its Settings. Keeping the operations in the core, driven from Settings, keeps one implementation of every operation and confirmation, and their tests. A per-command switch is what a page listing an extension's commands needs, as Raycast's has, and it lets a user turn off one command, such as a root provider, without the rest of its extension.

This decision makes no change to [ADR 0029](0029-the-ui-is-accepted-as-built.md)'s accepted look: the pages are composed of Settings' existing families (#99). It supersedes the places where earlier records put management "in Manage extensions" ([ADR 0016](0016-host-registers-global-hotkeys-for-commands.md)'s hotkey assignment among them): those choices are now made on the extension's page, or the Shortcuts page.
