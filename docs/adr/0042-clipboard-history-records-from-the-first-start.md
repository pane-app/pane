# Clipboard History records from the first start

Accepted 2026-10-07 by the user's decision (spec [#161](https://github.com/hoangvu12/pane/issues/161), "Clipboard History on by default, skipping concealed content"), implemented by [#166](https://github.com/hoangvu12/pane/issues/166). It amends [ADR 0020](0020-host-keeps-clipboard-history-for-an-extension.md), whose Clipboard History was "off until the user turns it on"; the rest of ADR 0020 stands, and so does [ADR 0023](0023-host-expires-clipboard-history-by-its-own-clock.md)'s expiry.

Raycast's Clipboard History has no on/off setting: it records from the start, skips what applications mark as concealed, and lets the user name Disabled Applications. A switch the user must find first makes Pane's history empty the first time they look, which is when they need it. So Pane's own Clipboard History default extension records from the first start: a fresh data folder keeps the first copy with no "Turn on clipboard history" step.

- **Only Pane's own.** The host records by default for its registered Clipboard History default extension alone (the package identity `default:clipboard-history`): its history is on while `clipboard-history.json` holds none for it. Any other package that uses `pane:extension/clipboard-history` starts off, as ADR 0020 says, and turns it on itself; the user did not choose it for recording. A copy of the Clipboard History package installed from a folder is such another package.
- **What stops it.** Disabling the extension still stops all observation (ADR 0001, ADR 0005): the watch follows the package's generation exactly as before. Pause Recording stops it until resumed, also across restarts; the file then holds the paused (or turned off) state, so a restart does not record again. Uninstalling with its saved data deleted forgets the state, and a reinstall records again.
- **What is not kept.** Concealed copies stay skipped on every system, as before (Windows' `ExcludeClipboardContentFromMonitorProcessing` and its siblings, macOS' `org.nspasteboard.ConcealedType`; X11 has no such format). The user's **Disabled Applications** — ADR 0020's excluded programs, matched by the program's file name — are honoured by the host before recording. On Windows the host now keeps the owning program's full path, so the history can show its icon; the exclusion still matches its file name, and a guest still receives the file name.
- **Where it is controlled.** The command's own management list is gone. Pause/Resume Recording, Keep History For, Clear History and Disabled Applications are in the view's Actions panel and on the extension's Settings page. The Settings page draws them as the package's preferences (`keepHistoryFor`, `pauseRecording`, and `disabledApplications`, a new `applications` preference type, picked with the system's application picker), but their values are the history's own state, read from and written to it by the host, so the Settings page, the Actions panel and what the host honours never disagree. Clear History asks first in both places.

Considered and not taken: making every package that imports the capability record by default (the host cannot know which packages use it before they call it, and the user chose only Pane's own); a manifest field asking to record by default (no other package needs it now); and keeping the controls as ordinary stored preferences mirrored into the history (two records of one state, which a change from either side would have to keep in step).
