# Hotkeys fall back to a keyboard hook, a refused shortcut is no longer an error, and the Windows key opens Pane on a fresh install

Accepted 2026-10-06 by the user's decision, after the [Raycast deep dive](../research/raycast-deep-dive.md#windows-integration). It amends [ADR 0016](0016-host-registers-global-hotkeys-for-commands.md) on Windows. A hotkey there is no longer only what `RegisterHotKey` accepts, and a shortcut Windows refuses is no longer an error ([global hotkeys](../hotkeys.md#assigning-one)). It also changes the fresh-install default of the Open Pane hotkey (#74), Ctrl+Alt+Space on Windows today. The rest of ADR 0016 stands: the core owns global hotkeys, Pane keeps them as its own record, a hotkey is registered exactly while its command is offered, and an extension cannot assign, read or declare one. [ADR 0037](0037-a-command-declares-its-mode-and-host-functions-decide-what-happens-after-it-runs.md)'s amendment, that a no-view command's hotkey runs it without showing the window, also stands. macOS and Linux keep their registration (Carbon hot keys, `XGrabKey`) and their defaults, Option+Space and Ctrl+Alt+Space.

**Registration first, the hook as fallback.** For each binding, the Windows adapter calls `RegisterHotKey` when the binding is a chord it can express and Windows accepts. Otherwise Pane recognises the binding in a low-level keyboard hook (`WH_KEYBOARD_LL`) of its own. That covers a shortcut Windows refuses because another application or Windows itself has it, a lone tap of a modifier such as the Windows key, a double tap, a side-specific modifier, and a key `RegisterHotKey` cannot tell apart. The hook is installed only while a binding needs it. A refused registration is therefore never an error to the user: the binding works through the hook, and its row says so and, for a known shortcut, what it did before. Only what no program can intercept (Win+L, Ctrl+Alt+Delete) and a binding another of Pane's bindings already has are still refused.

**The hook's safeguards.** Windows silently removes a hook whose callback runs past its timeout, so the hook must stay fast and must be watched. Its callback runs on a dedicated thread at the highest thread priority and only updates a small state machine. Its pages are locked in memory, so a trimmed working set cannot fault it past the timeout. A watchdog that reads raw keyboard input notices when key events stop reaching the hook and installs it again. The state machine re-reads the real state of the modifiers when an event contradicts it, after a lock or a UAC prompt, so no modifier stays stuck down. Every key Pane injects carries Pane's own tag, and the hook lets tagged keys pass. While an application running as administrator is in front, Windows does not deliver its keys to the hook of a normal process. Hook-based bindings do nothing there until a later UI Access helper lifts that limit, and their rows say so. The Windows power features specification sets the tap windows, the record's new syntax and the recorder, which holds keys back from Windows while it listens. It also sets an optional game mode that releases every hotkey while a game is in front.

**The Windows key opens Pane on a fresh install.** On Windows, once the hook fallback exists and can recognise the Windows key tapped alone, a fresh install's Open Pane hotkey is the Windows key alone, as Raycast's is. Until then the default stays Ctrl+Alt+Space. A tap means the Windows key pressed and released with no other key between. Pane masks the tap so that Explorer does not open the Start menu as well. Any other key pressed with the Windows key passes through, so Win+E, Win+R and the rest keep Windows' meaning. The Start menu stays reachable: from the Start button on the taskbar, and with Ctrl+Esc. An existing installation keeps the Open Pane hotkey it has; only a fresh install gets the new default, as only Raycast's new installs got theirs. Beside the Open Pane recorder, a "Use the Windows key" choice sets it in one step and says where the Start menu remains. This is Raycast's "Replace Start Menu", shown only while another hotkey is set. Proposed for the specification: a "Show the taskbar when Pane opens" setting for a user whose taskbar hides itself, so the Start button stays one click away, as Raycast offers; and Ctrl+Alt+Space registered instead, with the reason shown, when the hook cannot be installed.

ADR 0016 used `RegisterHotKey` because it needs no permission and was enough for chords of a letter, a digit, F1 to F12 or Space. It cannot express a modifier alone, a double tap or a side, and when another application has a chord it refuses, so the user had to find another. Raycast for Windows uses `RegisterHotKey` whenever Windows accepts the binding and its hook for everything else, and it treats a refusal as a reason to use the hook rather than an error. Its fresh installs default to the Windows key, with the Start menu kept on the taskbar. The user chose the same: one key that is always under the hand is the fastest way to open a launcher used many times a day. The cost is a hook Pane must keep alive. That is why the safeguards above are part of the decision, not details, and why the default waits for them.
