# File search indexes the user's home folder

Accepted 2026-10-06 by the user's decision, after the [Raycast deep dive](../research/raycast-deep-dive.md#windows-integration) (its decision 8). For file search, it supersedes several parts of [ADR 0017](0017-host-lists-a-granted-folder-for-an-extension.md), which was proposed by #29's implementation and never confirmed. The superseded parts are the one granted folder and the refusal to grant the home folder. Also superseded is the scan policy: 8 folders deep, 5,000 files and 20,000 entries, listed again for each visit of root search. So is the exclusion of an index and of file watching. What ADR 0017 left open, "an index or file watching", is decided here.

Other parts of ADR 0017 stand. The host, not the extension, reads the file system. Files are named by the ids the host gives them, and the host checks a file again before opening it. Its rule against opening programs and scripts stands until the file search specification revisits it. For packages other than file search, the folder grant stays as ADR 0017 describes, until that specification decides whether anything still needs it.

So Pane keeps an index of the names of the files and folders under the user's home folder, and Files searches that index instead of a listing. Contents are not indexed. The host builds and keeps the index, for the reason ADR 0017 gave for the listing. A guest walking the folders would hold the extension thread, which serves every extension's calls one at a time. A preopen would also let it name any path. The index is like Raycast's: a name index of the kind the MIT-licensed `minidex` crate builds. It skips hidden entries and what `.gitignore` files exclude. Exclusions the user can change start from caches, temporary folders, `node_modules` and application data (Raycast excludes `AppData`). Network and removable drives are left out by default. The index is Pane's own cache: it can be rebuilt at any time and is never extension data.

On Windows the index is kept current without administrator rights or a system service. When Pane starts, it catches up from the NTFS change journal instead of walking again, and falls back to a walk when the journal cannot account for what changed. While Pane runs, it watches the indexed folders for changes. Other systems keep the same index current with their own change notifications. Files remains a disableable default extension ([ADR 0001](0001-small-core.md)): indexing and watching run only while a package that searches the index is enabled, and disabling it stops both.

The goal is to be faster than Raycast. On the machine the research used, Raycast indexed the home folder's 450,097 entries in 12.9 s, with a 61.8 MB index on disk. Pane is to index the same folder on the same machine in less time. This is a measured target for the specification's tests, not a promise for every machine.

One folder of at most 5,000 files misses most of what people look for, and listing it again on every visit pays its cost every time. Raycast indexes the whole home folder once and keeps the index current, so a search is a lookup. ADR 0017 chose a single folder only to keep the first slice small.
