# Root search learns from what the user chooses

Accepted 2026-10-06 by the user's decision, after the [Raycast deep dive](../research/raycast-deep-dive.md#root-search) (its decision 3). It reverses a deliberate omission of #23, whose first ranking left out "frequency or recency, per-user ranking" ([root search](../root-search.md#matching-and-ranking)), and the stance #94 and #100 took that root search claims no recent use. It settles part of what [ADR 0006](0006-raycast-style-search-with-extension-providers.md) left to implementation, the ranking algorithm: the core still owns matching and ranking, and no extension learns or ranks anything.

So Pane remembers two things about each root result the user invokes from root search: the last queries typed when the user chose it, and a frecency score, a count of uses that decays with time. A use is recorded when the user invokes the result from root search (Enter, a click or its number chord), with the query then in the field. No use is recorded when the result's global hotkey opens it, or for a result without a lasting identity, such as a computed answer or a file. What is recorded is keyed by identity, as a quick slot is ([ADR 0026](0026-host-keeps-quick-slots-by-identity.md)): a registered command by its command id, and an indexed result, such as an application, by its own id under the command that supplies it. It is never keyed by a row's title or position.

For a typed query, what Pane learned is weighed with the title match in Raycast's order. The alias the user gave comes first, as it does now. Then come an exact title, then a result the user chose before for this query or one it begins, then how well the title matches, and frecency breaks ties between equally good matches. A learned query counts only while the result has been used recently. Where computed results and file results are placed (#27, #29) does not change. The blank query, as the user also chose, shows the pins first and then commands and applications ordered by frecency, with no section of suggestions such as Raycast's; the root search specification settles the list's label.

The values start from Raycast's measured ones, and the specification may tune them; they are not the user's decision. Raycast uses the last three distinct queries per result, counts them only for 17 days after the result was last opened, and halves frecency every ten days, never below the score of an unused result. Pane keeps what it learns as its own record in its data folder, following the house record rules of `aliases.json` and `quick-slots.json`. It is never extension data and is never sent anywhere. The kept queries are the user's own typing, so the specification is to settle how the user forgets them. Proposed: an Actions panel entry that forgets what was learned about one result (Raycast's Reset Ranking), and uninstalling a package forgets what was learned about its results, while disabling it does not.

Recent use was left out because #23's ranking was only a first one, and because the redesign had no source of recent use: a "Suggested · From your recent use" section would have claimed something Pane did not know. That reason ends once Pane records use. Learning is the largest gain for a launcher used many times a day. In Raycast, a result opened once from "ff" ranks near the top for "ff" from then on, even though "ff" matches its title weakly. The user chose to follow Raycast's mature behaviour where Pane had no reason of its own to differ.
