# Default extensions grow to include Switch Windows, System Commands, Run and Windows Settings

Accepted 2026-10-06 by the user's decision, after the [Raycast deep dive](../research/raycast-deep-dive.md#windows-integration). It extends the release's default set that [#60](https://github.com/hoangvu12/pane/issues/60) recorded as the user's choice: the calculator, Applications, Quicklinks, Files and Clipboard History ([installer](../installer.md#acquiring-the-default-extensions)). Those five stay as they are. [ADR 0001](0001-small-core.md)'s small core stands. The new features are default extensions, not core, and each runs on host capabilities that any extension may use, as Applications does under [ADR 0015](0015-host-finds-and-opens-applications-for-an-extension.md).

So four more default extensions join the set:

- **Switch Windows** lists the open windows as Alt+Tab does, with their applications' names and icons, and brings the chosen one to the front.
- **System Commands** holds no-view commands ([ADR 0037](0037-a-command-declares-its-mode-and-host-functions-decide-what-happens-after-it-runs.md)) that use documented Windows APIs: lock, sleep, hibernate, displays off, screen saver, log out, restart, shut down, volume, microphone mute, the Recycle Bin, dark mode, HDR and a few more.
- **Run** runs what Win+R runs and shares Win+R's own history in both directions.
- **Windows Settings** puts Windows Settings pages and Control Panel items into root search as indexed results.

Each is enabled by default, as the first five are, and each can be disabled on its own in Manage extensions, which is the opt-out, as for every default extension. They are acquired from Pane's artifact source like the others. An existing installation gains them as it gains any default extension it never had, while one the user uninstalled is not acquired again. They are Windows-only today, and each declares `windows` alone. Proposed for the specifications: only the Windows default set lists them, rather than installing on macOS and Linux packages that could only explain they are unavailable. Like every extension, they start nothing until they are used ([ADR 0005](0005-lazy-activation-and-managed-dependencies.md)). Each joins the set when its implementation lands: the first three with the Windows power features specification, Windows Settings with the applications specification's slice for Settings pages and Control Panel items.

**Restart and Shut Down force applications to close**, as the user chose, following Raycast, whose restart and shut down force applications closed the same way: an application with unsaved work cannot hold the system up. Log Out is not forced, as in Raycast. The confirmation stays: before each of the three, System Commands asks with a destructive confirmation, which offers "don't ask again" (ADR 0037). This decision replaces the specification's proposal not to force applications closed.

#60 chose five because those were the slices that had landed. These four are the Windows features a launcher user reaches for every day, and Raycast for Windows ships all of them built in, so a Pane user who must find and install each one has a poorer first day. Keeping each one a separate default extension, rather than one "Windows" package, lets the user turn off exactly the one they do not want. Run and Switch Windows overlap features of Windows itself, and the Settings results add many rows to root search, so enabling them could have been left to the user. Raycast enables its own by default, and the user chose the same.
