# Pane keeps quick slots as its own record, by identity

**Partly superseded:** [ADR 0027](0027-quick-slots-are-an-ordered-list.md) (accepted 2026-10-05) replaces the five positional slots, their empty places and the record's first version with an ordered list of pins without gaps or a limit (record version 2, which still reads version 1). That a slot holds an identity, never a row, how it is resolved, and the record rules still hold. Preserve the original text below; use ADR 0027 for the current arrangement.

Proposed 2026-10-05 by the implementation of #101, following the approved pin contract recorded on #100 and #101; not yet confirmed by the user. Root search's pinned home has five ordered quick slots the user fills with results, which must keep their order across restarts, never run a stale target, and survive a result's rename.

So a slot holds an identity, never a row: a registered command by its command id (an installed package's is `<package identity key>#<manifest command id>`), or an indexed result by its own id under the command that supplies it. Pane writes them itself, as a host record beside the host settings in its data folder, not as any package's extension data: `quick-slots.json`, `{ "version": 1, "slots": [ { "command": "<id>" }, null, { "command": "<id>", "result": "<id>" }, null, null ] }`, every slot in order, `null` for an empty one. It follows the house record rules `settings.json` and `aliases.json` follow: a record of another version, or one that is not valid (more than five slots, a slot that is neither empty nor a pin, an unknown field in a slot, a target pinned twice), is reported and never replaced while Pane runs; it is written atomically, one write at a time, each holding the arrangement as it is when it begins; a change applies at once and a write that fails puts back the arrangement the record last held and says why.

What a slot shows and does is resolved each time through the registry as it is then — the commands root search lists, and the indexed results Pane keeps — so a disabled, paused or uninstalled target keeps its slot, says why it cannot run and runs nothing, and the same identity installed or enabled again resolves it again. Invoking a slot resolves it once more and makes its call in the generation current then, so a late answer from replaced code is discarded as any other is. A cold visit asks a pinned result's command for its indexed results if it never answered, without a query.

Keeping slots as extension data was not used: they are the host's arrangement of many packages' results, and must outlive a package's uninstall so the slot can say so and be removed. Keeping row indexes or titles was not used: both change with the results, so a pin would silently move to another target. Keeping a computed answer, a granted file's handle or Pane's own rows was not used: none has an identity that outlives the query or the listing it came from. Putting the slots in `settings.json` was not used: that record is the Settings window's preferences, written whole on every choice, and a quick slot change is the launcher's.
