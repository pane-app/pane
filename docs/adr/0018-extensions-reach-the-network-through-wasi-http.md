# Extensions reach the network through wasi:http, sent by Pane

**Partly superseded:** the extension commands specification lowers the cap on a guest's linear memory from 512 MiB to 128 MiB, by the user's decision of 2026-10-06 ([Raycast deep dive](../research/raycast-deep-dive.md#decisions-needed), its decision 9). No ADR records it. Everything else here still holds. Preserve the original text below; the guest memory cap is 128 MiB.

Proposed 2026-09-28 by the implementation of #30, revised 2026-09-29 after its review; not yet confirmed by the user. An online search command must reach a web service. Before #30 a guest had no network access at all: the WASI context granted no sockets and no `wasi:http` was linked.

Pane links `wasi:http@0.3.0` (the `client` and `types` interfaces, from wasmtime-wasi-http 49.0.1's experimental p3 implementation) for every command, JS/TS and Rust alike. The requests are sent by Pane's own code in the host (`crates/pane-core/src/http.rs`: hyper over HTTP/1.1, TLS with rustls and the ring provider, trusting the system's certificates through rustls-native-certs), not the crate's default sender, whose bundled root list (webpki-roots) carries a license outside deny.toml. The guest SDKs wrap the client in a small `get` (`pane_guest::http`, `@pane/extension/http`); the standard bindings stay available. A request belongs to the guest call that made it: dropping the call (a stopped search, an ended generation) drops the request and closes its connection, and code of an ended generation cannot start one.

The host bounds every request, whatever the guest asks for (a guest may ask for shorter timeouts, not longer): 10 s to connect (TLS included), 20 s for the response's head, 10 s between two pieces of its body, 30 s for the whole request, and a 4 MiB body. Each ends the request with the matching `wasi:http` error code, which the guest receives as an ordinary error (so a stalled or endless service is the extension's error, not a hung call, a crash or a pause); a guest's linear memory is capped at 512 MiB besides. A package has at most four connections open at once (`connection-limit-reached` beyond). A system whose certificates could not be read is tried again on the next request, and a certificate the system does not trust is `TLS-certificate-error` ("the host's certificate is not trusted"). Redirects are not followed: a `3xx` is the guest's response.

This follows [ADR 0013](0013-require-wasi-03.md): a WASI 0.3 interface exists for the job, so no Pane-specific networking API was added, unlike [ADR 0015](0015-host-finds-and-opens-applications-for-an-extension.md), where WASI had nothing. A native helper ([ADR 0014](0014-optional-native-extension-helpers.md)) was not needed either. Raw sockets (`wasi:sockets`) stay denied: libraries built on `wasi:http` work, ones opening sockets themselves do not.

Under the trusted-code model ([ADR 0002](0002-trusted-extensions-and-open-distribution.md)) access is not gated per extension or per host: an extension reaches any address it names, including this computer's own services (`localhost`), the local network and link-local addresses such as the cloud metadata address `169.254.169.254`. What Pane does instead is make network use visible: checking a component at install, update or reload notes whether it imports `wasi:http`, the extension list says "Uses the network" on such a package, and a row of it lists the addresses (`host:port`) it tried to reach this session. A JS/TS command imports `wasi:http` only if its bundle uses it, as a Rust command's component imports only what its code calls, so the notice means something. A future allow-list must check the address a host name resolves to, at connection time, not the name alone: a name can resolve to a local or link-local address.

The search a command runs inside itself ([command search](../command-search.md), `pane:extension/command-search`) is a sibling of `query-command` (text typed into root search, sent when the user invokes the command); they are separate interfaces for now and may merge later. Its result record repeats root results' id, title and subtitle rather than reusing `root-result`, which carries an action a search result does not have; in the host all three kinds of results share one listing and one conversion to a row. Stopping a search drops the guest instance where it waits: Wasmtime offers no way to cancel one call of a component and keep its instance, as a dropped call's task stays in the store and would resume on the next call. The runtime waits 150 ms before it starts a search, so typing on stops each search before its command is asked or its instance dropped.

Costs: the p3 implementation is marked unstable upstream and may change with Wasmtime; the componentizer's snapshot stubs its async `send` (a change to Pane's patch 0003); proxies, HTTP/2 and per-extension network controls are not provided; the recorded addresses last only as long as Pane runs; packages installed before Pane recorded network use show it once reloaded or updated.
