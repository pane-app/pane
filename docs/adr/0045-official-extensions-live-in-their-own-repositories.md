# Official extensions live in their own repositories, and each Pane release pins the ones it sets up

Accepted 2026-10-08 by the user's decisions (and the `pane-app` organization the user created for them): the default extensions move out of Pane's repository "so when the user install the launcher, it would download default extensions from those repos, also anyone could contribute"; one repository per extension ("should we make 1 extension 1 repo?", a repository holding many extensions being "kinda weird" to them); and Pane shows its official extensions so the user chooses which to install. The details marked *proposed* were delegated and stay open to change by the specifications that implement them.

Q36 accepted that the installer carries no default extension and that first setup assumes internet access; that stands. What changes is where the defaults come from. They were to be acquired from Pane's own artifact source (`https://downloads.pane.sh/`), which was never deployed, so a release build could not finish its first setup; and their source lives in this repository's `guests/`, built against its `wit/` by path, where only Pane's maintainers work on them.

**Official extensions.** An official extension is one Pane's maintainers publish: the five default extensions (calculator, applications, quicklinks, files, clipboard history; #60), and any others they add. Each lives in a public repository of its own in Pane's GitHub organization, [`pane-app`](https://github.com/pane-app), named by its id (`pane-app/calculator`, `pane-app/clipboard-history`; the user confirmed the names 2026-10-08), as an ordinary Git-distributed package whose release tags (`v<semver>`, [ADR 0044](0044-a-git-repository-holds-one-extension-or-a-collection.md)) hold its built components. Anyone contributes to it through that repository. Pane marks official extensions as its own wherever it lists extensions.

**Pinned per release.** Each Pane release names, for every default extension, its repository and the commit of the release tag that release was tested with. At first setup Pane fetches exactly those commits with its own Git client ([ADR 0021](0021-pane-fetches-git-packages-itself.md)) and installs them (*proposed*). A commit id pins the bytes ADR 0021 writes, so no separate index or integrity file is needed, and no download host, redirect or rate-limited API is involved. A newer Pane release moves the pins forward. Between releases, a default extension updates from its repository's newer release tags that this Pane's extension API supports ([ADR 0046](0046-every-breaking-change-to-the-extension-api-gets-a-new-version.md)), under the updater and controls #127 specifies, in place of #127's artifact-source index (*proposed*).

**Identity.** A default extension keeps its default identity (`default:<id>`) whichever repository it is fetched from, so its saved data, quick slots, hotkeys and aliases, and what the host does for that identity (clipboard history recording from the first start, [ADR 0042](0042-clipboard-history-records-from-the-first-start.md); Files' use of the file index), are unchanged (*proposed*). The same repository installed by hand is a different package under [ADR 0012](0012-pi-style-source-identity.md).

**The user chooses at first setup.** First setup lists the official extensions with the default extensions ticked; the user unticks what they do not want. An unticked default is recorded as the user's choice, as an uninstall is, and is not set up again; it can be installed later from the Extensions group in Settings ([ADR 0043](0043-extensions-are-managed-in-settings-one-page-per-extension.md)). Without a connection, first setup explains it and offers each default again, as today.

**Rejected.** One repository holding every official extension (Raycast's, Zed's and Vicinae's stores, and Pi's built-in extensions, which live in Pi's own repository): the user's choice, accepting that a breaking change to the extension API needs a release in each repository, which ADR 0046's support window spreads out. Shipping the defaults inside the installer, which every launcher compared (Raycast, PowerToys Command Palette, Flow Launcher, Alfred, Albert, Vicinae) does: Q36 stands. GitHub release assets: their downloads redirect to another host, which Pane's downloads do not follow, and anonymous downloads are rate-limited per IP address, while Pane's Git client already fetches and verifies a commit. Pane's own artifact source: never deployed, and a server to run.

**Consequences.** The default extensions' source leaves `guests/`, which needs the published SDK and WIT (#128) so that they build outside a Pane checkout. The artifact source and acquired artifacts are no longer how default extensions arrive; the artifact source remains for Pane's own application updates, whose hosting stays open. Moving an official extension to a new API version takes a release of its repository before the Pane release that pins it.
