# Let the host grant, list and open one folder's files for an extension

**Superseded for file search** by [ADR 0034](0034-file-search-indexes-the-users-home-folder.md) (#126, implemented by #175): file search now uses the host's file index of the home folder, so the one granted folder, the refusal to grant the home folder, the scan policy listed again on each visit and the exclusion of an index and of file watching are replaced for it. What this record decided and ADR 0034 keeps still holds: the host, not the extension, reads the file system; files are named by the ids the host gives them; the host checks a file again before opening it. The granted folder below stays, unchanged, for packages other than file search; its refusal to open programs stays for its own `open-file` results, while file search follows [ADR 0037](0037-a-command-declares-its-mode-and-host-functions-decide-what-happens-after-it-runs.md) (Enter on a program shows it, only Run runs it).

Proposed 2026-09-28 by the implementation of #29, revised after its security review; not yet confirmed by the user. File search is a disableable default extension ([ADR 0001](0001-small-core.md), spec constraint 1), and the core owns matching, ranking and dispatch ([ADR 0006](0006-raycast-style-search-with-extension-providers.md)). A WASI 0.3 guest has no folders to read (Pane preopens none) and cannot open a file with the system's handler, so something must give it access to the folder the user chose, and that access must not reach further than the user meant, even though extensions are trusted code (Q9: the point is predictable behaviour, not isolation).

The host owns every step that decides what is reached:

- **The grant.** A package declares `"folderAccess": true` in `pane.json`; Pane then shows its own "Choose folder…" row at the top of the package's commands, which opens the system's folder picker. The host refuses the file system's root (or a drive's), the home folder itself, a hidden folder and network (UNC) paths, resolves the folder canonically and records it per package identity in its own `folders.json` beside `installed.json`, never in the extension's data. Disabling keeps it, uninstalling forgets it, "Stop sharing the folder" takes it back. The extension never supplies or sees a path.
- **The listing.** `pane:extension/files.list-folder()` takes no argument and never waits: it answers that no folder is granted, that Pane is listing it, or the listing Pane keeps for this visit of root search. The host lists on one worker thread per package, which takes only the newest request, after a short debounce, counting entries and checking for cancellation while it reads each folder, within fixed limits (8 folders deep, 5,000 files, 20,000 entries; regular files only, no hidden entries or links). The listing is kept for the visit, so keystrokes filter it, and stops when root search is left, the grant changes or the package's generation ends. A command that answered while its folder was listing is asked again once the listing ends, after every other result was shown, so a slow folder holds up no other extension's results.
- **Opening.** Files are named by opaque ids the host gave them in the package's latest listing. An `open-file(id)` result is shown with the host's own name for the file and its folder, whatever the extension titled it; one the host does not know is not listed. When invoked, the host checks again that the file is a regular file, not a link, whose canonical path is inside the canonical grant, and refuses programs and scripts (Windows executable and script types, macOS bundles and command files, `.desktop` files and anything with an executable bit), on every system.

Considered and not chosen: a WASI preopen of the chosen folder, letting the guest walk it with `wasi:filesystem`; the walk would run on the extension thread, which serves every extension's calls one at a time and cannot preempt a guest that does not yield (#18), and a preopen would let the guest name any path inside it to open. A folder field in the extension's own form, whose value the extension saves: the extension would then choose the path. A native helper ([ADR 0014](0014-optional-native-extension-helpers.md)): the host already lists folders and opens files natively. A whole-disk or watched index: the slice is one folder with a documented bound. Asking the user before opening a program was not chosen over refusing it, to keep the first slice simple.

Still open: several folders or scopes, an index or file watching, content search, network drives mapped to a letter (Windows) and network mounts (macOS, Linux), which the host cannot tell from local folders by their paths, and a confirmation that would let a user open a program deliberately.
