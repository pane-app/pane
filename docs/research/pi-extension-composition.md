# Pi extension-to-extension communication

Research for Q25, 2026-09-27. Scope: conventional coding-agent extensions at official commit [`2b0a123de98318c2ff8069661721ce0c3794c34e`](https://github.com/earendil-works/pi/tree/2b0a123de98318c2ff8069661721ce0c3794c34e), not the separate experimental Chord runtime. No extension code executed. Q25 subsequently accepted a host-routed call-and-result API for the launcher; see [ADR 0011](../adr/0011-extension-call-and-result-api.md).

## Shared event bus

Pi explicitly documents `pi.events` for communication with another extension. Its interface is `emit(channel: string, data: unknown): void` and `on(channel: string, handler: (data: unknown) => void): () => void`. Authors agree on channel names and payload shapes. This supports notifications and coordination; it is not a built-in typed request/result service API. Sources: [authoring guide](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/docs/extensions.md), [event bus](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/event-bus.ts#L3).

The implementation wraps Node's `EventEmitter`. Listener errors and rejected promises are caught and logged. `emit` does not await listener completion or return results. There is no built-in request correlation, timeout, provider discovery, payload validation, or dependency activation in this bus implementation; authors could build conventions on top. Source: [event bus implementation](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/event-bus.ts#L12).

The loader passes the same resolved bus to all extensions in the loaded set. Subscriptions return an unsubscribe function and are tracked for removal when the runtime is invalidated during replacement/reload. Failed initial loads also dispose their pending subscriptions. This cleanup removes listeners; it does not cancel arbitrary asynchronous work already started by a callback. Sources: [shared loader](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/extensions/loader.ts#L611), [tracked subscriptions and runtime invalidation](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/extensions/loader.ts#L185), [extension event wrapper](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/extensions/loader.ts#L436).

## Slash commands are another route, with different semantics

`pi.sendUserMessage('/command args', { expandPromptTemplates: true })` can dispatch a registered extension command. This option defaults to false. Conventional `pi.sendUserMessage` returns `void`; registered command handlers accept a string and return `Promise<void>`. Thus this is command triggering, not a structured result-returning invocation API. Sources: [extension action contract](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/extensions/types.ts#L1505), [registered command type](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/extensions/types.ts#L1342).

The session dispatches a matching slash command before the normal prompt pipeline and returns after handling it. It catches handler errors and reports them through the extension runner. An unknown command can continue through the ordinary prompt pipeline, so this should not be treated as an RPC call guaranteed to return a missing-dependency error. Sources: [prompt dispatch](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/agent-session.ts#L1614), [command execution](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/agent-session.ts#L1757), [message options](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/agent-session.ts#L2004).

## Scope of the comparison

In the inspected conventional `ExtensionAPI`, there is no general `executeCommand`/`invokeTool` method returning another extension's result. `getCommands` and `getAllTools` expose discovery information; `ToolInfo` excludes the tool's execution function. `pi.exec` executes an external command. This is a scoped API finding, not a claim that trusted JavaScript extensions cannot communicate through shared modules, subprocesses, or author-defined mechanisms. Source: [ExtensionAPI and ToolInfo](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/extensions/types.ts#L1531).

For our launcher, Pi provides precedent for a small communication primitive. The proposed explicit commands with structured inputs/results and JS/Rust routing would be an additional launcher contract, rather than a direct copy of Pi's event bus.
