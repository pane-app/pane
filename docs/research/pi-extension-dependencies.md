# Pi extension dependencies

Research for Q26, 2026-09-27, against conventional Pi coding-agent extensions at commit [`2b0a123de98318c2ff8069661721ce0c3794c34e`](https://github.com/earendil-works/pi/tree/2b0a123de98318c2ff8069661721ce0c3794c34e). The user subsequently accepted automatic installation of declared required launcher extensions in Q26; see [extension policies](../extension-policy-proposal.md). The Pi comparison describes a different package mechanism. No third-party extension executed.

## What Pi provides

Pi packages can bundle multiple extensions, skills, prompts, and themes. Ordinary imported runtime libraries belong in npm `dependencies`; Pi installs package dependencies for npm/Git sources. Local package dependencies remain the author's responsibility. Host-provided Pi libraries belong in `peerDependencies`, which managed installations suppress installing automatically. Other Pi packages can be bundled dependencies, but the documentation requires including them in the published tarball and explicitly exposing their resources through `node_modules` paths. Installed packages have separate module roots, so authors cannot assume unrelated packages share a dependency instance. Versioned npm sources and Git tags/commits are pinned. [Package documentation](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/docs/packages.md#declare-dependencies).

The parsed `pi` manifest contains resource lists (`extensions`, `skills`, `prompts`, `themes`). It does not define required/optional relationships between separately installed Pi extensions, dependency version ranges for those relationships, or their activation ordering. This is a scoped finding from that manifest and resolver, not a claim about every third-party Pi package. [Manifest parser](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/pi-manifest.ts).

## Installation is different from loading an extension

The resolver iterates configured package sources, then collects each source's declared or conventional resources. Automatic extension discovery explicitly skips `node_modules`; it does not recursively activate every installed dependency's extensions. However, explicit manifest paths can reach dependency resources, and directory entries can resolve their own `pi.extensions` or `index.ts`/`index.js`. Thus an author can assemble a package that exposes dependency extension files, while merely putting another Pi package in npm `dependencies` is not equivalent to declaring a separately managed, active extension dependency. [Package manager: source resolution, discovery, and resource collection](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/package-manager.ts#L1252).

Settings filters and `pi config` select which discovered resources load; an empty resource-type array loads none of that type. [Resource selection documentation](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/docs/packages.md#select-package-resources). The resource loader filters to enabled extension paths before loading factories. In this path, no dependency graph re-enables disabled extensions or marks consumers blocked because another extension is disabled. Ordinary module imports remain authors' code and are distinct from registered extension activation. [Resource loader](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/resource-loader.ts#L607).

## Implication for Q26

Pi is a precedent for packages carrying libraries and explicitly bundling several extension resources. It is not evidence that installing extension A automatically installs, resolves versions for, and activates a separately managed extension B through a dedicated extension dependency declaration. Our proposed required/optional extension relationships would be an additional launcher feature. Q26 subsequently settled the launcher's installation, disabled-state and conflict direction; exact dependency/update implementation remains open.
