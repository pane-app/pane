# Pi and Tinycast: Node compatibility for Q18

Research date: 2026-09-27. This is a read-only source audit; no extension or repository code was executed. Pi is pinned to `2b0a123de98318c2ff8069661721ce0c3794c34e`, Tinycast to `6fc6aa1b909ca24e3cd25e35c078a7c808ca34a9`. Q18 was subsequently accepted as managed real Node; see [ADR 0008](../adr/0008-managed-node-for-javascript-extensions.md).

## Pi

Pi uses a real general-purpose JavaScript runtime. The published package declares Node `>=22.19.0`. Its documented extension model is trusted in-process code; extensions may declare npm dependencies in a nearby `package.json`. Pi installs runtime dependencies for managed npm/Git packages, while local package dependency installation remains the author's responsibility. Host-provided Pi libraries have special resolution rules to avoid duplicate runtime identities. This provides broad ecosystem access, not a promise that every npm package works in every distribution or operating system. [Package metadata](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/package.json), [extension documentation](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/docs/extensions.md), [package dependencies](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/docs/packages.md#declare-dependencies).

The loader uses `jiti` for TypeScript imports. It selects aliases or embedded host modules according to distribution and recognizes Bun binaries, Node SEA binaries, bundled Node, and source TypeScript execution. Its `tryNative: false` option in embedded-module mode should not be misread as a documented ban on native addons; it is a module-loader option, not a product compatibility policy. [Loader](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/packages/coding-agent/src/core/extensions/loader.ts).

The inspected standalone build script uses `bun build --compile`, targeting macOS/Linux/Windows on x64/ARM64, and copies platform helpers alongside each executable. Therefore that standalone build path runs Bun, while npm installation uses Node. Do not describe every Pi distribution as identical to Node or assume arbitrary native modules are automatically portable. This audit did not run native-addon compatibility tests. [Binary build script](https://github.com/earendil-works/pi/blob/2b0a123de98318c2ff8069661721ce0c3794c34e/scripts/build-binaries.sh).

## Tinycast

Tinycast evaluates extension bundles in macOS JavaScriptCore. It implements selected Node APIs as JavaScript/native bridges; it does not embed Node. Its synthetic `process.version` value does not establish actual Node compatibility. [Runtime](https://github.com/abue-ammar/tinycast/blob/6fc6aa1b909ca24e3cd25e35c078a7c808ca34a9/Tinycast/Features/Extensions/Service/ExtensionRuntime.swift), [process shim](https://github.com/abue-ammar/tinycast/blob/6fc6aa1b909ca24e3cd25e35c078a7c808ca34a9/Scripts/raycast-runtime/src/node-shims.js#L163).

Its command loader evaluates a single CommonJS bundle. `require` consults a registry of supplied modules, with a package-root fallback; unknown names throw. There is no ordinary Node disk-module or native `.node` addon loading path in that loader. **Inference:** bundled pure-JavaScript npm packages can work if their runtime requirements are covered, but arbitrary Node packages/native addons are not supported just because the extension was bundled successfully. [Complete module loader](https://github.com/abue-ammar/tinycast/blob/6fc6aa1b909ca24e3cd25e35c078a7c808ca34a9/Scripts/raycast-runtime/src/modules.js).

Concrete source limitations: `fs.watch` and `child_process.fork` throw; raw `net`, `tls`, `dns` and worker-thread functionality uses refuse-on-use stubs. Unsupported module imports can succeed because properties are manufactured lazily, then throw when used. Successful startup/rendering therefore does not establish full workflow compatibility. Other APIs do have implementations, including filesystem, subprocess and HTTP functionality; it would be inaccurate to say all networking or processes are unavailable. [Node shims](https://github.com/abue-ammar/tinycast/blob/6fc6aa1b909ca24e3cd25e35c078a7c808ca34a9/Scripts/raycast-runtime/src/node-shims.js#L1585).

The installer omits `node_modules` when copying built extension files and uses an installed Node/package manager when building from source. Running prebuilt bundles without Node is different from authoring/building packages without tools. [Installer](https://github.com/abue-ammar/tinycast/blob/6fc6aa1b909ca24e3cd25e35c078a7c808ca34a9/Tinycast/Features/Extensions/Service/ExtensionInstaller.swift).

## Implication for this launcher

Recommendation, not a new decision: prefer a managed actual Node runtime for the JS/TS extension path when ordinary Node/npm capability is the goal. A Tinycast-style shim layer creates an ongoing compatibility implementation project. GPUI CE rendering does not require choosing the shim approach. Keep native addon prebuilds and runtime/OS/architecture compatibility explicit; Rust extensions are a separate SDK/distribution route. No comparative application-memory benchmark was performed here.
