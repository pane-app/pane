# Pane: current decisions

Reconciled 2026-09-28 against the saved interview, ADRs, policy document, test reports, and user messages available in the current conversation. This is a decision index, not a new spec or implementation authorization. It does not reconstruct a verbatim pre-compaction transcript.

Not reconciled since: the Settings and shortcuts work ([#70](https://github.com/hoangvu12/pane/issues/70)), the launcher UI ([#61](https://github.com/hoangvu12/pane/issues/61)), the Windows UI port ([#90](https://github.com/hoangvu12/pane/issues/90)) and ADRs [0026](adr/0026-host-keeps-quick-slots-by-identity.md)-[0028](adr/0028-the-launcher-draws-a-background-image-the-user-chooses.md). Where those differ from a row below, they win; [HANDOFF](HANDOFF.md#where-the-work-stands) says where the work stands.

Use this file for current status; use the linked records for detail and rationale. Later explicit user instructions take precedence. **Accepted** is a product decision, **provisional** is a direction awaiting detail or validation, **superseded** is historical, and **deferred** is outside the initial scope or postponed. An untested requirement can still be accepted; test success does not turn an assistant recommendation into user approval.

## Runtime direction and evidence

The user reopened the Node/native choices to pursue WIT bindings plus a Wasmtime runtime, then explicitly required **WASI 0.3, not 0.2**. This is the current architecture under evaluation, with component-native async required by [ADR 0013](adr/0013-require-wasi-03.md). A mixed P2/P3 result does not meet that requirement. The shared helper, per-generation stores and public WIT/SDK design remain engineering proposals, not a completed runtime.

**QuickJS is provisional.** The user requested that its findings be recorded and further experiments deferred during grilling. The JS engine is replaceable in principle; no universal Node/npm compatibility, long-lived fork or final engine selection is accepted. WIT generates interfaces/bindings; it does not itself execute JS. TS was transpiled for the experiments.

| Saved evidence | What it establishes | What it does not establish |
| --- | --- | --- |
| [Rust std P3 probe](research/p3-std-spike/README.md) | A pinned nightly + SDK 34 build runs ordinary std filesystem/environment/clock checks with P3-only imports. | All Rust crates, Tokio, or every target working unchanged. |
| [Patched QuickJS P3 probe](research/qjs-p3-port-spike/README.md) | Fuse/Zod, native async, file streams, 20 sequential same-instance calls and error cases pass on Windows with P3-only imports. | Production readiness, concurrent-call isolation, cancellation, leak freedom or universal JS library compatibility. |
| [P3-only embedded host](research/p3-only-host/README.md) | Accepts the patched JS/Rust guests and rejects stock mixed-version JS. | Production helper IPC, crash supervision or launcher integration. |
| [GPUI probe](research/wasi03-gpui-spike/README.md) | Windows rendering of guest-produced JSON, file-based view replacement and click recording. | Actual guest hot reload, live Wasmtime/GPUI event round trips, custom drawing, IME/accessibility parity or macOS/Linux support. |

The QuickJS integration patch removes the old adapter/reset path, links real P3 libc, removes P2 registration and moves async task bookkeeping to separate TLS. Build flags export TLS metadata. These are componentize-qjs integration changes, not changes to the JS engine source. The snapshotted Math.random/performance state that repeated across fresh instances is fixed in a candidate patch with a regression check. On Linux, JS and TS samples of `wit/extension.wit` run through `pane-core`. [Linux validation](research/js-backend-validation/README.md). **Decided 2026-09-28 (#2):** build JS/TS extensions with pinned upstream componentize-qjs (`e563c6d6`) plus Pane's patch queue (P3 port and snapshot reseed; #22 adds a third, stubbing async host imports during the snapshot, which Wasmtime 49 makes unnecessary), propose the patches upstream, and do not maintain a long-term fork. QuickJS remains replaceable if upstream diverges. [Patch and detailed report](research/qjs-p3-port-spike/README.md).

Recorded same-workload comparison: component 6.67 to 9.44 MiB; median fresh cached CLI peak process working set 30.71 to 36.81 MiB (three samples). Different optimizations mean this is not an isolated measure of WASI3 overhead, launcher idle memory, or additive per-extension cost. Keep the earlier smaller synchronous benchmarks separate. The spec's "caches" (US61) is therefore covered only in part: the extension's own cache (`cache.json`) is removed, while Pane's shared compile cache is intentionally left alone, because its entries are keyed by component bytes and may be shared with another installed package (Wasmtime trims it itself; it holds no extension data). #41 adds [deleting retained data](extension-data.md#deleting-retained-data) from Manage extensions: one row per identity with retained data (its title, source and what is kept), a confirmation, then every kind Pane keeps for that identity is deleted and its record dropped, without the extension's code; data that cannot be deleted stays listed and is explained. The confirmation lists Cancel first and selected, so Enter keeps the data, as for uninstall; `installed.json` is read again before deleting, so a source another Pane installed again meanwhile keeps its data. **Provisional choice of #41, pending user confirmation:** deleting removes every kind, including a cache or credential an earlier uninstall could not delete. Uninstalling required dependents (#44) remains open. **Local credentials are plain text** in `credentials.json` in Pane's data folder (mode 0600 on macOS and Linux; the folder's permissions on Windows), not in the system keychain: accepted for now because the [data policy](extension-policy-proposal.md#disable-cache-data-and-uninstall) treats credential handling as "lifecycle behavior, not secret isolation from trusted code", so any extension or program running as the user can read them. Keychain storage (macOS Keychain, Windows Credential Manager, Secret Service) is an open item. Clearing re-reads `cache.json` first, so a value another Pane process saved meanwhile is kept.
- Saved state survives reload; arbitrary transient state requires explicit extension support. Successful compilation followed by failed startup does not restore an older version automatically. Cleanup cannot reverse arbitrary external side effects. [Reload policy](extension-policy-proposal.md#development-reload).
- Automatic failure recovery is not the same operation as user-requested disable/uninstall with dependent handling. Expected operation errors should not pause a whole extension; shared-runtime crashes may lack a known culprit. These distinctions are proposed mechanics supporting Q39, not tested guarantees. [Recovery proposal](launcher-design-interview.md#proposed-automatic-recovery-behavior-for-q39).
- Source distribution flexibility does not imply end users compile arbitrary source-only packages without tools. Native integrations may need prebuilt helpers. [Setup policy](extension-policy-proposal.md#end-user-installation).

## Explicitly unresolved or deferred

These remain open design/validation work in the specification and implementation issues:

1. Final JS engine, upstream patch/fork strategy, runtime packaging/topology and initialization fixes.
2. Public WIT/SDK contracts, language parity, UI/event/custom drawing, input/IME/accessibility and host/helper IPC. #20 adds the first standard-control slice, [forms](forms.md): an item can open a form with single-line text and single-choice fields and a submit button, which the extension validates per field or as a whole (Rust, JavaScript and TypeScript). #21 adds the first [custom view](custom-views.md): an item can open a view the extension draws from filled rectangles and text and that receives arrow/Home/End keys and primary-button pointer press, drag and release, held in a guest `custom-view` resource that Pane drops when the view closes; its example is a color picker in all three languages. Still open: other controls (multi-line text, checkboxes, dates, lists in forms), events beyond submit and those view events, richer drawing (paths, images, text styles, scrolling, layout), views composed of several focusable parts or standard controls, real input-method and screen-reader verification on every OS, accessibility actions and invalid state, and the rest of the SDK surface. #22 adds [operations](operations.md), one extension calling another's published operation through Pane (Rust, JavaScript and TypeScript on both sides); #42 adds [declared dependencies](dependencies.md), called by id and installed with the caller, and #45 [npm sources](npm.md#dependencies-from-npm) for them; and #46 [Git sources](git.md#dependencies-from-git); still open for operations: streams or typed schemas beyond JSON text and version ranges.
3. Cancellation, hangs, concurrent work, stale generation replies, reload/disable resource cleanup and fatal shared-runtime recovery. #10 settles user-requested disable of a local package: it applies at once and is recorded in `installed.json`, the package's commands leave root search, its instances are dropped, the runtime refuses its calls and it cannot save settings, while its [extension settings](../guests/README.md#keeping-settings) (Rust, JavaScript and TypeScript) are kept across restarts. #14 adds [generations](generations.md): every call into a package belongs to the generation current when it was asked for, which a disable, reload or update ends; a call not started is then never started, one waiting inside the guest is stopped at once (its instance and store are dropped, so nothing after its `await` runs), a result completing anyway is discarded, and the stopped code's host imports (reading or saving data, operation calls, applications) are refused; stopping drops the whole instance, so its in-memory state is lost, a cost that cancelled searches (#29) now pay; in a call chain, stopping a target answers its caller at once and stopping a caller stops the operation it waits for. Leaving a screen only discards answers. Since #18 a guest computing without yielding is preempted at each epoch tick and stopped after 5 seconds of computing ([pausing](pausing.md#when-an-extension-stops-responding)). Still open: no time limit on waiting (a clock, an operation) and no user cancellation; a guest looping on Pane's host calls is barely charged and a host call that never returns gets no notice (a wall-clock notice naming the running package, without blame, is a proposed follow-up; [pausing](pausing.md#when-an-extension-stops-responding)); carrying an open command's state over an update or reload (none is carried); #11 adds manual [reload](../guests/README.md#reloading-a-package-while-pane-stays-open) of one enabled local package from **Manage extensions…**: a replacement that fails the install checks leaves the working code running; one that passes replaces the managed copy, the old instances stop (an open command, form or view of the package closes, and a late answer from the old copy is not shown) and each available command is started and asked for its view; a startup failure stops its instances again and is reported with Retry and diagnostics (also on standard error), without restoring the earlier code. Only a fatal initialization counts as a failure to start (a trap, a component that cannot load or type-check, an instantiation error); an error the guest returns from its view, such as asking the user to sign in first, is an expected operation error and does not (#16). Since #16 a startup failure [pauses](pausing.md) the package, persisted across restarts, until Retry, a reload, an update or a disable. Retry of a paused package (#16) starts every available command at once, as a reload does: the same **provisional** exception to lazy activation, extended so that a Retry reports whether the package starts while the user is looking; revisit both together. A reload, an update from **Install extension from folder…** and an enable/disable of the same package exclude each other; the later one is refused with "<title> is reloading" or "is updating". Starting every available command at reload is a deliberate, **provisional** exception to [lazy activation](adr/0005-lazy-activation-and-managed-dependencies.md): it reports a broken start while the author is looking, rather than at the next use; reload on save (#12/#13) keeps it, so each successful build starts every available command; revisit it once a command's start can be expensive. Settings are kept and no transient state is carried over (no extension API for it). Rebuild/reload on save is [development mode](development-mode.md) (#12/#13), whose builds have no timeout; background services and timers ([scheduled work](schedules.md) since #47, and a package's [global hotkeys](hotkeys.md) released when it is disabled, since #32 to #34); dependents of a disabled package (#43 asks first and disables them together, [dependencies](dependencies.md#disabling-a-required-dependency)); operation calls, which have no timeout either (a call is owned by the guest call that made it and never outlives it, and stops with any generation in its chain; [operations](operations.md)); and more than one Pane process on the same data folder, whose records are replaced atomically but not locked, so one process can lose another's last settings or install write (single-instance is a later concern).
4. Package manifest/artifact format beyond the minimal local `pane.json` v1 of #9 (title, version, extension API, one component per command; [format](../guests/README.md#packaging-and-installing-a-local-extension)), dependency/resource addressing beyond `local:` and `npm:` sources (#42 adds [dependency](dependencies.md) ids, cycles and partial installation for local folders; #45 adds [npm packages](npm.md) and `npm:` dependencies), private npm registries and credentials, SSH and private Git repositories, automatic updates of unpinned npm packages and tracked Git branches (#50), and staged update activation (#45 adds npm packages; #46 adds [Git packages](git.md) and `git:` dependencies, tracked branches and pinned tags and commits). #19 adds Q34's [platform availability](platform-availability.md): an optional `platforms` list in `pane.json` for the package (a package for other systems is explained, not installed) and for each command, and on list items (an unavailable action stays listed with its reason and is never called); architectures are not covered (native helper files per operating system and processor came with #15, [helpers](helpers.md)), and only Linux X11 has run the native check. #9's update is not coordinated with a running or open command of the package.
5. API version signaling, deprecation/migration details, persisted-state schema/migration ownership and recovery limits. Until the first published release, the pre-release extension API 0.1 changes shape between slices without a version bump (#19 added `platforms` to `item`, #21 the `custom-view` resource and `open-view`; #22 only adds an import and an optional export, so it refuses no earlier component; #29 adds the case `open-file` to `root-results`' `root-action` variant, so every component exporting `root-results` was rebuilt, and adds the import `pane:extension/files`, which the host world offers every component; a JavaScript or TypeScript component imports it only when its `package.json` sets `"pane": { "files": true }`, though all of them were rebuilt for #29 because each build's inputs include every Pane WIT file). A component built against an older shape declares the same `apiVersion`; Pane refuses it when the package is previewed or installed, and when a command built into Pane loads, by type-checking the component's exported functions against those Pane calls, from the component's type alone without running guest code: "it was built for an older extension API shape: rebuild it against Pane's current extension API 0.1 (`get-view`: type mismatch for field items: expected record of 6 fields, found 4 fields)". The check uses Wasmtime's `ComponentFunc::typecheck` and `types::Component::instance_type`, public but `#[doc(hidden)]` (the calls bindgen's generated code makes), so a Wasmtime upgrade may need it adjusted; the fixtures `old-api` (a real older shape) and `mismatched-api` (every export by name, one record different) keep it tested.
6. Supported OS versions/architectures/Linux desktops, release validation matrix and measured resource/startup/interaction targets. #4 adds the Linux workload, the /proc sampler and the targets' shape ([measurement record](research/resource-measurements.md)); no number exists or is confirmed yet, and the macOS and Windows measurements are not started.
7. Installer acquisition/retry/cache mechanics; app/runtime update delivery; default clipboard retention (7 days provisionally since #36) and other concrete settings defaults.
8. The licensing split is decided and applied; release notice generation (cargo-about plus a manual supplement) and the per-release Corresponding Source procedure remain to be exercised on a real artifact.
9. Catalog and historical-version picker are explicitly deferred; Python/C# are later languages. Neither is silently restored to launch scope.
10. [Root search](root-search.md) (#23) open items. Accessibility: GPUI CE lacks real active-descendant support, so the selected result is reported as the focused node while the caret is in the query field, and a screen reader may announce results instead of echoing typing; G2 cannot pass until GPUI CE exposes `active_descendant` on the focused field or a workaround is found, and no screen reader has been run. Extension points later tickets need: results computed from the query exist since #27 (a command declaring `rootResults` in `pane.json` exports `pane:extension/root-results`, asked on every non-blank query; each command's results are listed above title matches as soon as it answers, although calls still run one at a time, so a slow or hung command delays those asked after it until #29 and #18; a computed result copies text or, since #28, opens an `http://` or `https://` link with the system's handler ([quicklinks](quicklinks.md)); answers for an older query are discarded), with the calculator as a disableable default extension in Rust whose expression scope is documented in [root search](root-search.md#the-calculator); results supplied ahead of the query exist since #24 to #26 (a command declaring `indexedResults` exports `pane:extension/indexed-results`, asked once per visit of root search on the first non-blank query, kept and ranked by title like commands, listed only for a non-blank query; the only action opens an application), with [applications](applications.md) as a disableable default extension in Rust over a host capability `pane:extension/applications` with one adapter per system (Start menu shortcuts and the Apps folder's packaged apps, application bundles, XDG desktop entries), behind a host-side list rescanned in the background, usable from Rust, JavaScript and TypeScript. **Provisional, pending user confirmation:** the host-capability split ([ADR 0015](adr/0015-host-finds-and-opens-applications-for-an-extension.md)) rather than a native helper, applications listed only for a non-blank query, and commands ranking before applications on equal title ranks. Localized names and icons are not covered, and only Linux X11 has run the native launch; provider ranks are still open (#29 adds cancellation but no ranks). **Provisional, pending user confirmation:** computed results rank above every title match; this is an implementation choice of #27, not a user decision. Removal: disable, update and uninstall (#40) change a package's root results. **Provisional, pending user confirmation ([quicklinks](quicklinks.md), #28):** a quicklink targets only an absolute `http://` or `https://` URL, with no placeholders; quicklinks are kept as the extension's content (#39); they reach root search as computed results, so they rank above title matches and are not listed for a blank query (moving them to indexed results, with an open-url indexed action, would rank them by title with commands and applications); the edit form keeps a field's value when it is left empty, since forms have no initial values; and Pane refuses an `open-url` action for any other scheme. **Provisional, pending user confirmation ([global hotkeys](hotkeys.md), #32 to #34, [ADR 0016](adr/0016-host-registers-global-hotkeys-for-commands.md)):** the user assigns a global hotkey to an installed command in Manage extensions; Pane keeps it in its own `hotkeys.json` (not extension data) and registers it (Windows `RegisterHotKey`, macOS Carbon hot keys without any permission, X11 key grabs) only while the command is offered, so disable releases it, enable restores it and uninstall releases and forgets it (whether or not saved data is kept); a press opens the command in Pane's window; Ctrl, Alt or Super is required, Ctrl (Command) with a single character and a per-system reserved list are refused, and one shortcut opens one command; Wayland is explained as unavailable (no portal support yet); there is no summon hotkey of Pane's own and no extension API for hotkeys. **Provisional, pending user confirmation ([aliases and fallbacks](aliases.md), #31):** the user gives an installed command a one-word alias (at most 32 characters, unique among commands compared caselessly: NFC and full Unicode case folding through the `unicase` crate, not locale-aware) in a form in Manage extensions, and turns a query-taking command into a fallback there; Pane keeps both in its own `aliases.json` by command id (not extension data), so copies from other sources stay distinct, disable hides them without forgetting them or enabling anything, update and reload keep them (a missing command's choices are shown as not active and can be forgotten), and uninstall forgets them; the answer is cleared from the status line when the query changes and a late one is discarded; alias and fallback rows name their source when another offered command has the same title; Manage extensions shows a choice as not active with why (disabled, paused, unavailable on this system, the package cannot load, the command gone or no longer taking a query); a manifest command id cannot contain `#`, so a command id's package part is exact and uninstalling one source never forgets another's choices (hotkeys too), and a failed write never restores an uninstalled package's choices; Pane's own alias form starts with the current value, while an extension's form fields still always start empty (the only prefilled field is Pane's own). **Provisional, pending user confirmation ([file search](files.md), #29, reworked after its security review, [ADR 0017](adr/0017-host-lists-a-granted-folder-for-an-extension.md), proposed):** file search is a disableable default extension in Rust, Files, over a host capability `pane:extension/files` rather than a WASI preopen, a folder field the extension saves or a native helper; the host owns the grant: a package declaring `"folderAccess": true` gets Pane's own "Choose folder…" and "Stop sharing the folder" rows at the top of its commands, the folder comes from the system's picker (a debug build's `PANE_TEST_CHOOSE_FOLDER` stands in for it in the smokes), Pane refuses the file system's or a drive's root, the home folder itself, a hidden folder and UNC/network paths (on Windows, from the text before any file system call), and records the canonical folder per package identity in its own `folders.json`, not extension data (kept while disabled, forgotten on uninstall); Only Linux X11 has run the native open; the macOS and Windows smoke phases record the opened path through a debug build's `PANE_TEST_OPEN_FILE_LOG` instead of running the real handler, and have not run yet.

The specification identifies bounded validation tasks and open contracts. A consequential new product choice still needs a user decision before implementation depends on it.
